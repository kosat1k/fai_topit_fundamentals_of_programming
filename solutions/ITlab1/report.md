## 3 Задание 3. Подсчёт ссылок и время жизни объекта

### 3.1 Подсчёт ссылок

Код исследования изменения счётчика ссылок и результат его выполнения приведены на рисунке 7.

*Рисунок 7 – Изменение счётчика ссылок (код и результат)*

```python
import sys

data = [1, 2, 3]
print("После создания:", sys.getrefcount(data))

alias = data
print("После создания alias:", sys.getrefcount(data))

container = [data]
print("После помещения в контейнер:", sys.getrefcount(data))

del alias
print("После del alias:", sys.getrefcount(data))

container.clear()
print("После очистки контейнера:", sys.getrefcount(data))
```

Результат:

```text
После создания: 2
После создания alias: 3
После помещения в контейнер: 4
После del alias: 3
После очистки контейнера: 2
```

**Почему `getrefcount()` показывает на единицу больше?** При передаче `data` в `sys.getrefcount(data)` Python на время вызова функции создаёт дополнительную временную ссылку на этот объект (аргумент функции). Эта ссылка тоже учитывается счётчиком, поэтому результат всегда на 1 больше, чем реальное количество ссылок в коде.

**Что увеличивает счётчик ссылок?** Любое действие, создающее новую ссылку на объект: присваивание `alias = data`, помещение в контейнер `[data]`, передача в функцию, создание атрибута `obj.attr = data`, возврат из функции.

**Что уменьшает счётчик ссылок?** Действия, убирающие ссылку: `del alias`, переприсваивание переменной, выход переменной из области видимости (например, конец функции), удаление из контейнера (`container.clear()`, `list.remove()`), перезапись элемента списка или словаря.

**Почему `del alias` не удаляет объект?** В Python переменные – это не сами данные, а имена (ярлыки), указывающие на объект в памяти. Команда `del alias` убирает именно ярлык из текущего пространства имён, уменьшая счётчик ссылок на 1. Сам объект существует до тех пор, пока на него ссылается хотя бы одна переменная или контейнер. Только когда счётчик станет равным нулю, память будет освобождена. В приведённом примере после `del alias` объект остаётся живым, потому что на него всё ещё указывает `data`.

### 3.4 Ответы на вопросы для анализа

**1. При каком условии подсчёт ссылок позволяет освободить объект?**

Когда счётчик ссылок на объект становится равным нулю, то есть на него не указывает ни одна переменная, контейнер или другая ссылка.

**2. Всегда ли освобождение Python-объекта означает немедленный возврат памяти операционной системе?**

Нет. Python освобождает объект из своей внутренней памяти (арены и пулы аллокатора), но саму память операционной системе обычно не возвращает: она остаётся в резерве для будущих объектов. Возврат памяти ОС происходит редко и зависит от реализации аллокатора.

**3. Чем сильная ссылка отличается от слабой?**

Сильная ссылка увеличивает счётчик ссылок и удерживает объект в памяти. Слабая ссылка (`weakref`) не увеличивает счётчик и не мешает объекту быть удалённым: когда исчезают все сильные ссылки, объект уничтожается, а слабая ссылка становится «мёртвой» (возвращает `None`).

### 4.3 Ответы на вопросы для анализа

**1. Как возникает циклическая ссылка?**

Когда два или более объекта ссылаются друг на друга (напрямую или через цепочку), замыкая круг: A → B → A. В коде это часто получается через `append`, присваивание атрибутов или вложенные структуры.

**2. Почему объект с ненулевым счётчиком ссылок может быть недостижим?**

Если объекты держат друг друга ссылками, но на них больше никто не ссылается извне (нет имён в переменных, контейнерах, стеке), они взаимно «поддерживают» счётчики друг друга. Из программы к ним нет пути, поэтому они являются мусором, хотя счётчик не равен нулю.

**3. Зачем сборщик разделяет объекты по поколениям?**

Для оптимизации: большинство объектов умирают молодыми, а долгоживущие проверять дорого. Новые объекты (поколение 0) проверяются часто, пережившие сборку переходят в старшие поколения и проверяются реже – это экономит время.

### 5.2 Рост списка

Код для наблюдения за ростом списка приведён в листинге 1.

*Листинг 1 – Наблюдение за ростом списка при добавлении элементов*

```python
import sys

lst = []
prev_size = sys.getsizeof(lst)
print(f"len=0, size={prev_size}")

for i in range(100):
    lst.append(i)
    new_size = sys.getsizeof(lst)
    if new_size != prev_size:
        print(f"len={len(lst)}, size={new_size}")
        prev_size = new_size
```

**1. Увеличивается ли размер списка после каждого `append()`?**

Нет. Размер меняется скачкообразно – только в те моменты, когда внутренний массив указателей заполнен и Python вынужден выделить новый, более вместительный массив. Между этими скачками размер списка (по `sys.getsizeof`) остаётся неизменным, хотя длина растёт. Например, переходы происходят примерно на 1, 5, 9, 17, 25, 33, 41… элементах, но не на каждом.

**2. Почему список резервирует место с запасом?**

Чтобы избежать дорогой операции перевыделения памяти при каждом добавлении элемента.

**3. Чем длина списка отличается от объёма выделенной памяти?**

- Длина (`len(lst)`) – сколько элементов реально лежит в списке.
- Объём памяти (`sys.getsizeof(lst)`) – сколько памяти зарезервировано под указатели, включая запас на будущие элементы.

```python
current, peak = tracemalloc.get_traced_memory()
tracemalloc.stop()
print(f"list: текущий {current/1024:.1f} КиБ, пик {peak/1024:.1f} КиБ")

tracemalloc.start()

current, peak = tracemalloc.get_traced_memory()

```

Результат:

```text

range: текущий 0.0 КиБ, пик 0.0 КиБ
```

Так происходит потому, что `list` хранит все значения в памяти, а `range()` хранит лишь начало, конец и шаг (то, что по факту нужно для его работы), а значения вычисляет по мере обращения.

### 5.4 Итоговый анализ

Способы уменьшить потребление памяти:

1. Использовать слабые словари и ссылки в коде, где это уместно (задание 3). Например, если мы храним объекты класса в словаре, затем переназначаем переменную на другой объект, то прежний объект удаляется из словаря за ненадобностью.
2. Использовать поверхностное копирование вместо глубокого там, где это уместно (задание 2), а уместно это довольно часто.
3. Избегать циклических ссылок в коде (задание 4).

### 5.5 Итоговая утилита

Итоговый код и результат работы утилиты `memory_report.py` приведены на рисунке 16.

*Рисунок 16 – Итоговая утилита memory_report.py (код и результат)*

```python
# ВОССТАНОВЛЕНО: этой части нет на скриншоте, проверьте по своему файлу
import tracemalloc
from sys import getsizeof

counts = {
    "[]": 0,
    "list(range(10))": 10,
    "tuple(range(10))": 10,
    '"0123456789"': 10,
    "10": 1,
    "None": 1,
}

spis = [
    ("[]", "пустой список"),
    ("list(range(10))", "10 элементов список"),
    ("tuple(range(10))", "10 элементов кортеж"),
    ('"0123456789"', "строка 10 символов"),
    ("10", "целое число"),
    ("None", "None"),
]

# сначала измерение: результаты сохраняются в структуре данных
results = []
for expr, name in spis:
    tracemalloc.start()
    obj = eval(expr)
    current, peak = tracemalloc.get_traced_memory()
    tracemalloc.stop()
    results.append((name, counts[expr], getsizeof(obj), current, peak))

# затем форматирование и вывод
print("Сценарий | Элементов | Размер, Б | Текущая, Б | Пик, Б")
print("-" * 70)
for name, count, size, current, peak in results:
    print(f"{name} | {count} | {size} | {current} | {peak}")
```
